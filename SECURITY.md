# Security and privacy

ESP32Health is a Home Assistant app. Its web interface accepts production requests only from Supervisor Ingress (`172.30.32.2`); it exposes no host port and is intended for HA administrators. Home Assistant handles ingress login. A developer-only fixture can construct a local test application; the production entrypoint always requires the Supervisor environment and ingress protection.

`homeassistant_api: true` gives the Python backend privileged HA API access using `SUPERVISOR_TOKEN`. The credential stays in backend memory, is never returned to the browser or stored in configuration, and is not logged. Do not copy it into bug reports. No Supervisor-management, Docker-socket, host-network or hardware permissions are requested.

The backend permits an explicit allowlist of HA read commands. The browser can read sensor metadata, device suggestions and mapped sensor values, save the app's own configuration, and request at most 24 hours of history for configured entities. It has no generic service/API proxy. Unselected sensor values are redacted. The app itself does not modify ESPHome firmware or device settings. The only write capability to HA is a fixed notification method for configured, explicitly enabled advisory alert rules: `persistent_notification.create` or available `notify.mobile_app_*` services. The browser cannot pass arbitrary actions, payloads, targets or notification text. Notification targets are enumerated with `get_services`; the backend constructs all message fields. No phone notification is sent until a user enables and saves a rule.

Configuration is written atomically to `/data/config.json`, with revision checks against concurrent edits. It contains entity mappings and labels, not credentials. A bounded local log of the last 50 alert events and delivery/cooldown metadata is atomically stored with mode 0600 in `/data/alerts.json`. It may contain personal sensor information and is included in app backups. Delivery failures are shown locally without logging payloads. There is no generic service endpoint or automatic retry of uncertain sends. History stays in Recorder; CSV exports may contain personal sensor information. There is no external analytics SDK, CDN or cloud database.

For security reports use GitHub private vulnerability reporting if available, or an existing private channel to the owner. Do not post real sensor exports, tokens or unredacted household diagnostics in public issues.
